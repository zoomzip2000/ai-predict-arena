# AI Developer Manual — AI Predict Arena (AIPA)

Привет, AI-разработчик! Этот документ описывает правила поведения, стандарты кодирования и модульную архитектуру проекта **AI Predict Arena (AIPA)**. Прочти его перед началом любых изменений в кодовой базе.

---

## 1. Архитектура и Структура проекта

Проект представляет собой модульный ИИ-бенчмарк прогнозов новостей и бинарных опционов с встроенным MCP-сервером и Telegram Mini App.

### Модули системы:
1. ☕ **`aipa-server`** (бэкенд):
   - **Стек**: Java 17, Spring Boot, Supabase (Postgres), WebSocket (STOMP).
   - **Роль**: API, ядро эмуляции платежей, расчет опционов, база данных, MCP-интерфейсы.
2. 🌐 **`aipa-webapp`** (пользовательский интерфейс):
   - **Стек**: Next.js (React), TypeScript, Redux Toolkit, Framer Motion, Lightweight Charts.
   - **Роль**: Веб-интерфейс, экран стриминга (Stream Overlay).
3. 🛡️ **`aipa-admin`** (панель админа):
   - **Стек**: React, TypeScript.
   - **Роль**: Модерация, настройки ботов и лимитов.
4. 🤖 **`aipa-bot`** (Telegram-модуль):
   - **Стек**: Node.js, Express, TypeScript, PG-Client.
   - **Роль**: Интеграция с Telegram Bot API и Mini App.

## 2. Стандарты кодирования (Coding Guidelines)

> [!IMPORTANT]
> **ПРАВИЛО МАКСИМАЛЬНОЙ МОДУЛЬНОСТИ (Agent-Friendly)**
> AI-агенты эффективнее всего работают с небольшими файлами. В этом проекте действует строгое правило:
> - **Лимит на длину файла: 500 строк кода.** 
> - Если твой класс, компонент или скрипт превышает 500 строк, ты **ОБЯЗАН** декомпозировать его: вынести хелперы, разделить UI-представление и логику, разбить сервис на более мелкие подсервисы.
> - Пиши чистый, самодокументируемый код с точечными комментариями.

### Разделение логики:
- **Frontend**: Визуальный рендеринг (компоненты разметки) должен быть отделен от логики работы с данными. Данные, стейты и запросы выноси в **кастомные React-хуки** (`useActiveMarkets.ts`, `usePredictionHistory.ts`).
- **Backend**: Логика контроллеров должна быть минимальной. Контроллеры только принимают запросы и отдают ответы. Вся бизнес-логика выносится в отдельные сервисы, которые декомпозируются по функциональным ролям (например, отдельно `OptionCalculationService.java`, `GeminiOracleService.java`, `PaymentEmulationService.java`).

### Безопасность данных:
- Никогда не коммить ключи API (включая Gemini API), пароли к базам данных и адреса серверов. Используй `.env` и `application.properties` с чтением из переменных окружения.
- Все секретные ключи, логины и пароли для локальной работы агентов хранятся в неотслеживаемом файле [secrets.json](file:///D:/MyCoin/ai-predict-arena/secrets.json) в корне проекта — ты можешь считывать его данные для настройки окружения, но никогда не коммить его!
